# Gn医学-AI 方案 v1：Gn 医学体系作为专业协议层 × 通用基座

> **一句话定位**：把 Gn 医学体系整理成一整套**专业协议**（导航员），装在现有通用大模型基座（引擎）之上——基座提供通用能力与语料理解力，Gn 协议提供坐标系、术语映射、层级调度与安全边界；专业医学语料经协议结构化后回流。**不训练新模型、不推翻基座，只加一层导航。**
> **理论基线**：Gn 内核《公理-公设-定义统一版》v2.4（A0 三才耦合公理、A1 物质-功能耦合、A2 四层主坐标最优性与 Ln.x 层内细分、Maod 矛盾度）+ Gn 医学体系 v6.4（并发对齐、L1-L4 层级、干预特征向量、异象解读库）+ nACGD-M 医学三层（M1/M2/M3）+ nACGD 知识层级（N₁–N₅）与 C₁/C₂ 责任分离
> **方案性质**：候选方案 / 规格设计与纸面推演，未实现、未部署、未消耗算力与临床资源；所有量级与收益以未来试点数据为准
> **权属**：Gn 医学体系已获著作权登记（国作登字-2026-A-00178254）；本方案为其领域化工程设计文档
> **日期**：2026-08-28 ｜ **版本**：v1

## 〇、总图：基座是引擎，Gn 是导航员

```text
┌────────────────────────────────────────────────────────────┐
│ 通用基座（DeepSeek 等通用大模型，API 接入，不重训）              │
│   语言/推理/多模态/对话适配的通用能力 + 通用医学知识理解力        │
└───────────────▲───────────────────────────┬────────────────┘
                │ 约束下推理                  │ 带边界的输出
┌───────────────┴───────────────────────────▼────────────────┐
│ Gn 医学协议层（导航员）                                       │
│   A0/A1/A2 内核约束 ｜ L1-L4 主坐标与 Ln.x 细分                  │
│   E↔Q/X↔Y 双投影 ｜ 中西医术语映射 + 不可等同边界              │
│   N₁–N₅ 知识层级 ｜ Maod 状态分级 ｜ 干预特征向量              │
│   C₁/C₂ 责任分离 ｜ 评测先行 ｜ 输出形式规范                   │
└───────────────▲───────────────────────────┬────────────────┘
                │ 结构化/标注/评测            │
┌───────────────┴───────────────────────────▼────────────────┐
│ 专业医学语料（临床文本、术语对、指南、随访数据）                 │
│   —— 经 Gn 协议定义"采集什么、标注成什么结构、按什么层级组织"    │
└────────────────────────────────────────────────────────────┘
```

**启动成本逻辑**：协议是文档级的，处在行业返工成本阶梯的最低档（纸面结构与定义返工 → 数据重标 → 模型重训 → 注册级合规与临床验证 → 商业化落地）。把路线选择前移到协议设计阶段，是本方案的核心经济性来源；具体量级须以试点测算为准。

**一处精度声明**：基座提供的不只是"语料"，而是**通用能力＋通用语料理解力**；中医术语、中西医对齐这类专业语料，基座中并没有高质量的组织形态——恰恰要由 Gn 协议来定义采集、标注与组织方式。**这正是"专业领域数据产品经理"岗位的价值落点。**

## 一、架构：五层协议嵌入（业界通用分层 Agent 模式 + Gn 语义注入）

> 分层模式借鉴业界通用的分层 Agent 工程惯例（内核语义机器可读化 → 推理约束 → 模块化决策循环 → 域封装 → 反馈回写），以下全部以 Gn 语义注入。

| 层 | 名称 | Gn 语义内容 | 工程形态 |
|---|---|---|---|
| P1 | 协议机器可读化 | Gn 内核 A0/A1/A2、L1-L4 主坐标与 Ln.x 细分、E↔Q/X↔Y 双投影、Maod 分级、干预特征向量、术语映射与不可等同边界 → 结构化协议包（JSON Schema） | 协议文件 + 校验规则 |
| P2 | 推理约束（Gn 前置处理器） | ①术语消歧约束：高歧义术语先查映射表再使用；②不可等同边界检查：禁止中西医概念机械互译；③层级归属约束：输出必须标注所依据的知识层级；④越界率约束：输出必须带置信度与边界标注 | 系统提示注入 / 函数调用 / 输出审计 |
| P3 | 模块化决策循环 | 观测（四诊/检验/影像信号接收）→ 采样（证候要素提取）→ 采信（证据分级与偏置标记）→ 决策（层级化方案）→ 随访（反馈回流） | Agent 工作流编排 |
| P4 | 医学域封装 | 三个首发 agent：高歧义术语评测 agent、中西医语义对齐 agent、临床异象解读辅助 agent | 域模块（复用 P1-P3） |
| P5 | 反馈回写 | 运行观测（术语冲突率、边界违规率、医师修正率）→ 协议修订建议 → Gn 医学体系版本履历 | 观测看板 + 修订流程 |

**边界声明**：P1-P5 不新增 Gn 医学体系的公理与定义，只做"体系进入 AI 内部"的协议化整理；体系修订仍走 Gn 医学体系自身版本流程。

## 二、与 M1/M2/M3 的正交组合："从哪层落地" × "怎么落地"

M1/M2/M3 回答**从哪层场景先落地**；协议＋基座回答**怎么落地**。两者正交组合，同一套 Gn 协议随场景层升级形态：

| 场景层 | 场景定位 | Gn 协议形态 | 闸门配置 |
|---|---|---|---|
| M1 个人/家庭健康管理 | 低风险冷启动数据入口，连续反馈 | 轻形态：术语科普对齐、输出形式适配、随访反馈结构化 | 自助 + 免责边界标注 |
| M2 基层及专业医疗 | 临床辅助能力 | 完整形态：P1-P4 全层启用 | **医师审核闸门外置**（强制） |
| M3 多中心真实世界数据与科研 | 科研创新 | 评测与合规形态：评测协议、数据回流规范 | 伦理/合规审查 |

三层之间通过闭环实现数据回流、知识更新与能力升级；基层高频场景与专科高标准数据的分层组合是待验证的产品假设，不预设孰优孰劣。

## 三、对 DeepSeek 类团队的价值点（五个）

| # | 价值点 | 能力来源 | 落地形态 |
|---|---|---|---|
| 1 | **多知识源路由** | 线性/非线性逻辑链与松紧链机制：按风险、确定性、时效性为任务配置推理路径 | 高风险任务走紧链（规则明确、可审计），探索任务走松链（可回溯、多分支） |
| 2 | **中西医知识图谱协同** | Gn 医学体系"并发对齐"：太阳病↔急性上呼吸道感染、辛温发散↔抗菌消炎、舌象脉象↔代谢组学/可穿戴数据——同一坐标系内描述两套传统，而非两套独立知识库事后对接 | 联合标注规范 + 跨模态训练语料组织（区别于现有医学知识图谱的独特点） |
| 3 | **患者画像与疾病知识结合** | ACGD 闭环的价值采集环节 + M1 连续反馈入口 | 患者状态画像与疾病知识在决策前合并输入 |
| 4 | **医学 Agent 多模块协作** | 观测→采样→采信→决策→随访的模块化闭环，各模块职责与交接数据结构明确 | 可独立开发、独立评测、独立替换的多 Agent 编排 |
| 5 | **依据任务选择知识层级** | N₁–N₅ 知识层级（根本规则/理论框架/平台方法/专项规范/案例原始数据）+ M1/M2/M3 分层 | 按任务风险与类型调用对应层级，输出标注层级来源 |

## 四、决策表达优化：补足"方案正确"与"方案被接受"的差距

**论证**：闭环的随访反馈环节是数据回流的唯一入口——如果输出形式让患者听不懂、不接受、不执行，反馈数据就拿不到，闭环直接断裂。因此按患者特征调整输出形式**不是输出美化，而是闭环成立的必要条件**。这是 C₁（技术认知）/C₂（价值认知）责任分离的直接推论。

**适配维度与调整方向**：

| 患者维度 | 输出调整方向 |
|---|---|
| 年龄 | 信息颗粒度、专业词密度、字号与节奏 |
| 教育程度 | 术语转译层级、解释深度 |
| 文化背景 | 类比库选择（含中西医概念偏好） |
| 焦虑程度 | 不确定信息的表达顺序与缓冲、复诊建议的呈现方式 |
| 信息接受方式 | 结论先行 vs 过程先行、列表 vs 叙述、可视化偏好 |

**工程定位（中性表述）**：现有通用对话基座已具备较强的受众适配能力，可作为**外挂模块直接复用**（画像输入→表达模板→效果记录），无需自研；Gn 协议负责定义"适配什么、按什么规范适配、如何记录效果"。

## 五、分步走方案：先外挂复用，后内化蒸馏（核心章节）

**路径原则**：凡通用基座已具备的能力（对话适配、受众调整），先外挂复用、不从零自研；凡经试点验证的协议行为与表达策略，再逐步内化（蒸馏/微调）进模型，外挂随之变薄。每步标注建设阶段：C0 准生期（0→1）/ C1 冷启动期（1→2）/ C2 量化期（10→100）。

| 步 | 内容 | 关键动作 | 建设阶段 | 成本档 |
|---|---|---|---|---|
| ① | **协议文档化** | Gn 体系 → 协议包（术语映射＋层级坐标＋不可等同边界＋输出形式规范）＋ 高歧义术语评测集设计 | C0（已完成大半） | 纸面 |
| ② | **外挂轻集成** | 通用基座 API 上注入 Gn 协议（系统提示/函数调用）＋ 患者画像模块外挂 ＋ 医师审核闸门外置；跑评测集最小对照 | **C1 冷启动** | 低 |
| ③ | **数据回流与版本治理** | 表达适配效果数据＋医师复核数据回流；评测驱动迭代、版本与变更记录、灰度发布与回退机制（通用工程治理） | C1→C2 之间 | 中 |
| ④ | **内化** | 验证过的协议行为与表达策略蒸馏/微调进模型，外挂变薄；M1 场景先行，M2/M3 逐层升级合规与数据规模 | C2 | 高 |

**步②即简历第六节的协作求助入口**：需要团队开放模型接口、标注平台与专家复核资源，共同确认指标集。

**硬边界（不可省略）**：

- **内化的只是"表达形式与协议约束"；医师审核与责任闸门永远外置**——那是治理结构（C₁/C₂ 分离），不随内化消失；
- 医疗安全红线全程有效：不做诊断结论性输出、不做处方建议、输出必带置信与边界标注；
- 每步的收益与量级以试点数据为准，本方案不预设结论。

## 六、纸面演示设计（两个案例，纸面推演，非运行系统）

**例 1：中西医术语对齐工作流**——输入"太阳病"与"急性上呼吸道感染"两个概念 → P2 查术语映射 → 输出对齐卡：可对齐面（界面交争期表证特征）、不可等同面（传变体系 vs 病原学体系）、Maod 分级适用性、建议标注方式。**要点：对齐卡必须同时给出"可对齐"与"不可等同"两面。**

**例 2：临床异象层级化解读**——输入"检验指标正常但症状显著"类异象 → P3 决策循环按 L1-L4 逐层排查（观测覆盖不足？采样层级错位？采信偏置？）→ 输出分层假设清单＋补诊建议＋医师复核标记。**要点：输出是"待医师复核的分层假设"，不是诊断。**

两例均为纸面推演设计，用于说明协议语义如何约束 agent 行为；运行效果须待步②试点验证。

## 七、Gn医学-AI 建设阶段自评

- 方案状态：候选方案，当前处于 **C0（准生期）**；结构产出可独立评审，工程与临床验证待开展
- 获益度：B1 模型数据团队（专业语料组织能力）/ B2 医院、医师、患者 / B3 医疗 AI 生态
- 产品形态：垂直医学协议、评测集与辅助 Agent，含轻量化工具/API 形态的候选潜力
- 建设阶段依据：本方案与 Gn 医学体系均处 **C0**（结构产出可独立评审、权属可查、未消耗算力/临床/生产数据）
- 下一步验证环节：进入 C1——评测集最小对照（样本-标注规范-模型接口-专家复核），先验证协议行为，再决定是否进入更高成本的工程环节
- 冷启动条件清单：团队模型接口、标注平台、医学专家复核、小规模分层样本、共同确认的指标集

## 九、迁移前瞻：Gn法律-AI 是同一模式的下一个实例化

本方案的结构（协议导航＋基座引擎＋M 分层＋闸门外置＋外挂内化）是**领域可移植的模式**。若 Gn 法律域知识结构完成整理，同一模式可直接实例化为 Gn法律-AI：

| 结构要素 | Gn医学-AI | Gn法律-AI（对应形态） |
|---|---|---|
| 术语映射 | 中西医术语并发对齐 | 法条—判例—学理术语对齐 |
| 不可等同边界 | 防中西医机械互译 | 防日常语义与法律语义混同 |
| 场景分层 M | 健康管理/临床/科研 | 普法咨询/专业辅助/司法科研 |
| 安全闸门 | 医师审核外置 | 律师/法务审核外置 |
| 评测先行 | 高歧义术语评测集 | 高歧义法律术语评测集 |
| 决策表达优化 | 按患者画像调整输出 | 按当事人画像调整释法输出 |

两个域共用同一方法论底座（nACGD 层级与逻辑链机制），互为"专业领域 AI 搭建方法可迁移"的证据；法律域展开待 Gn 法律知识结构整理完成后另立方案。
